# @de/ui-provenance

The UI Provenance Instrumenter. It gives reviewable elements in a React micro
frontend a durable identity, and resolves a selected rendered element back to
the MFE, build, source file, component and JSX location that produced it.

It is preview-only, and it is not a feedback tool. The Preview Review Layer
consumes it; comments, threads, screenshots and approvals live there.

## Why a registry

A line number is not an identity. Neither is a CSS selector, a DOM index, or a
React internal. All four change under ordinary work, and an anchor that moves
when the code is reformatted is worse than no anchor at all.

So identity is assigned once, recorded in a source-controlled registry, and
preserved by matching structure rather than position:

```
.ui-provenance/registry.json     committed with the application
prv_01J8W3K6J4B8N4W8T4M2F0A6Q9  opaque, immutable, never derived from location
```

Measured on a 151-element golden fixture across a twelve-edit suite: **100%
retention** for formatting-only edits, **100%** across the ordinary-edit suite
including file moves and component renames, and **zero false reattachments**.
The numbers are regenerated by `pnpm test` into
[validation/stability-report.json](validation/stability-report.json).

Zero false reattachments takes precedence over retention. A visible orphan is
safer than feedback attached to the wrong control.

## Entry points

| Import | What it is |
|---|---|
| `@de/ui-provenance/core` | Types, schemas, identity, confidence, error codes |
| `@de/ui-provenance/compiler` | Discovery, fingerprints, registry sync, transformation |
| `@de/ui-provenance/vite` | Vite adapter |
| `@de/ui-provenance/webpack` | Webpack adapter and loader |
| `@de/ui-provenance/runtime` | Browser selection and anchor resolution |
| `@de/ui-provenance/eslint` | Source-time validation rules |
| `@de/ui-provenance/module-federation` | Module Federation 2 runtime plugin |

`ui-provenance` is also a CLI: `init`, `sync`, `check`.
